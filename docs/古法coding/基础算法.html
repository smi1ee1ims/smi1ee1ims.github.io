双指针

关键：
初始化位置。i,j分别在两端，还是在同一端？

遍历过程：i,j移动，一定会经过最佳位置。只需要判断是每一步是该i移还是j移动。

如果i,j初始在两端，那就交替往中间移动。

如果i,j在一段，那就都往另一边移动。

还有可能从中间往两边。

移动的规则：到底这次谁移动。往往是做比较，选出两个情况中的一种。

优化目标：

·贪心算法。需要求出最优情况的i,j位置。需要思考一下，哪一种移动，对于最优化目标没用，那么就不要这样移动。

·数据处理。通过双指针把一个数据处理成指定格式的数据。一般i就是“当前加工位置”，j往后推，用来和i比对是否需要加工。

应用：

滑动窗口（前缀和，覆盖子串（结合哈希）等））

接雨水（两边往中间交替）

相交链表（求交点，双指针分别从两个链表头遍历，再遍历对方链表，相遇时即交点）

哈夫曼编码（堆排序）

要求构成哈夫曼树，往左为0，往右为1，节点的编码形如1010。越小的节点编码越大。

输入：字典结构的节点键值。 {'A': 45, 'B': 13, 'C': 12, 'D': 16, 'E': 9, 'F': 5}

输出：键 编码。

注：heapq.heapify后会自动排序，之后pop出的一定是最小的。这样处理后heap就不再是单纯的list了，不能直接用list下标了，要用pop弹出。

tree={'A': 45, 'B': 13, 'C': 12, 'D': 16, 'E': 9, 'F': 5}

import heapq
# 构建堆排序的序列基础
heap=[[weight,(key,'')] for key,weight in tree.items()
# 堆排序，使得形成一个上大下小的堆。
heapq.heapify(heap)
#每次取最小的两个节点（节点块）弹出，直到只剩一个节点则说明完成排序编码。
while len(heap)>1:
	low1=heapq.heappop(heap)
	low2=heapq.heappop(heap)
	# 最小的往左子树放，编码添0
	for item in low1[1]:
		item[1]='0'+item[1]
	for item in low2[1]:
		item[1]='1'+item[1]
	# 两个最小节点合并，重新压入堆中
	# 前面的weight按值相加，后面的节点序列则是拼接合并。
	new_node=[low1[0]+low2[0]]+low1[1:]+low2[1:]
	# 新节点压入堆中，此时堆的长度已经-1了。
	heapq.heappop(heap,new_node)
	
# 最后排序输出(先按编码的长度排序，再按编码值排序，最后就是按值从大到小的序列)
heap=sorted(heapq.heappop(heap)[1:],key=lambda x:(len(x[1]),x)
滑动窗口

在一个长的串里，找出满足条件的短串。

关键就是左右边界的进、出。左边往左一个，窗口内就少一个元素，其他不变；右边往右一个，窗口内就多一个元素，其他不变。

结合 双指针、哈希

前缀和

定义：一个数组里，一个元素前面所有数字的和，包含自身。用一个list来记录每个位置的前缀和。通常会在前缀和list前面补一个0，用来兼容首个位置。

作用：快速计算某个窗口的和。有点像求落差。这样，sum( list[ i:j+1 ] )=qzh[ j ]-qzh[ i ]

结合 双指针、哈希。

递归

常见的递归模型，本质就分两种：

  • 一种是阶乘公式，f(n) = n * f(n-1)；
  • 另一种是斐波那契公式，f(n) = f(n - 1) + f(n - 2)。一般情况下，还需要处理本层的任务，因此，扩展公式是：f(n) = n + f(n - 1) + f(n - 2)。
  • 把要解决的问题，抽象为数学模型描述，如果可以用以上两种公式模型套进去，就可以用递归。

比如这道题，本质就是阶乘的模型，当前问题是 f(n)，从 list1 和 list2 中找出较小的那个，作为 n，剩下的所有节点构成的问题作为 f(n-1)。最终，f(n) = 找出 n + 解决 f(n-1)。

再比如汉诺塔问题，本质就是斐波那契模型的扩展公式。

超时问题解决方案：

1.not in 判断用集合，不用链表。

判断元素not in 集合为O(1)，用list则为O(N)。

创建seen的时候用seen=set()。

2.遍历节点时，一次性读取当前节点的值和next节点。【显著提高速度】

不要循环开始先读取值，循环末尾再读取下一次值。

例如：

3.去除冗余的列表【显著】

修改算法后，不需要的数据结构不要再维护了。

比如l1.append(node)如果已经用不到了，但是这个简单的append()操作还是会显著增加运行用时。

4.剪枝【显著】【字符串处理】

例如113（L2-008）,当字符串剩下的部分不可能再产生最大值了，就不往下遍历了。

虽然只是在部分退出，没有改变时间复杂度的等级，但是实际上减小了时间复杂度。
